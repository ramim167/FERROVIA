# FERROVIA feature and UX audit

Audit date: 2026-09-24

## Verified working

- Passenger registration and sign-in
- Train search, class selection, seat selection and passenger entry
- Seat hold, payment, ticket creation, ticket listing and cancellation
- Notifications and read state
- Train search suggestions, live status and stop timeline
- Operator arrival/departure progression through trip completion
- Admin service inspection, train editing, route editing, automatic trip issuing and operator assignment
- Admin creation of a complete train service
- Desktop, tablet and mobile navigation without horizontal overflow
- Frontend lint, backend integration tests and production build

## Fixed in this audit

1. **Incorrect network fares (high)**
   - The old rules varied by train type and did not match the supplied 300 km reference.
   - All trains now use Shovan `1.666667/km`, Snigdha `3.666667/km`, and AC Berth `6.000000/km`, with zero fixed base fare.
   - At 300 km the backend returns exactly `500`, `1100`, and `1800` after currency rounding.

2. **Missing AC Berth inventory (high)**
   - The seeded service exposed AC Seat instead of Berth.
   - Fresh seeds now create AC Berth. Migration `003` adds Berth fare rules, coaches and 24 berth seats to existing trains.

3. **Dhaka-Rangpur direct route stored as 10 km (critical)**
   - The generated W-771/W-772 route endpoints now store the supplied 300 km in both directions.
   - Migration `003` corrects existing databases.

4. **Route generator silently invented distances (critical)**
   - `generate_sql.js` used `stop index * 10`, so all generated routes appeared valid while containing fabricated values.
   - Generation now requires a numeric `Distance_From_Source_KM` source value and stops with a clear error when it is missing.

5. **Memory-mode UI claimed PostgreSQL was active (medium)**
   - User-facing text now says database/server-backed instead of claiming a specific database engine.

6. **Fare precision too low (medium)**
   - `RATE_PER_KM` only stored two decimals, which cannot represent `500 / 300` or `1100 / 300` accurately.
   - The schema and migration now use six decimal places.

7. **Calculated fares were not rounded to railway-friendly amounts (medium)**
   - Every calculated fare is now rounded upward to the next multiple of ৳10.
   - For example, ৳1,933.33 becomes ৳1,940 while an exact ৳1,800 remains ৳1,800.

## Still open

1. **Expanded route distances require a verified source (critical data blocker)**
   - The supplied workbook has 1,993 stop rows but no distance column.
   - The checked-in expanded SQL contains 301 route origins and 1,692 non-origin stops generated by the old 10 km placeholder rule. Only the two user-specified Dhaka-Rangpur endpoint rows can be corrected from the supplied facts.
   - These remaining values must not be presented as real railway distances. Add a verified `Distance_From_Source_KM` column to the workbook, then rerun the generator. It now refuses to fabricate missing values.

2. **Default local environment depends on an external PostgreSQL host (medium setup issue)**
   - In this workspace, plain `npm run dev` could not reach the configured remote database. `DATABASE_MODE=memory` starts successfully and is the reliable zero-setup path.

3. **Coverage gaps (low)**
   - The automated browser suite does not click every support accordion, every filter combination, every notification action on mobile, or every admin form validation branch.
   - No accessibility scanner, keyboard-only sweep, or screen-reader audit is currently configured.
